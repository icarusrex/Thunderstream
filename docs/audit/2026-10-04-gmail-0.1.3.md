# Gmail 0.1.3 verification, 2026-10-04

Tested code: `197b3c2f0855c92315d166f51ae1b96b6e0dd4c5` from PR #3, using the same installed core artifact as the [local native run](2026-10-04-native-0.1.3.md). Thunderbird 157.0.1 on macOS 27.0.1. The owner added and authenticated a Gmail account in the disposable profile and explicitly approved normal mailbox synchronization. Only marked synthetic messages were opened and operated on. Calendar and contact synchronization were skipped.

All five messages were addressed to the same Gmail account. Messages 1 and 2 were sent through native Thunderbird SMTP; messages 3 and 4 were seeded through the matching Gmail connector; message 5 used Thunderstream Send & Archive and native SMTP. The connector account was verified to match the Thunderbird account before use. Account identifiers and raw mail headers are retained only in local test evidence.

## Results

| Check | Observed result |
|---|---|
| SMTP / IMAP round trip | Message 1 appeared in Sent and Inbox, with its synthetic body displayed from an IMAP URL. Message 2's receipt was also confirmed against Gmail. |
| Sender selection | Explicit Gmail selection for Compose and the recipient-matching Gmail suggestion for Reply opened with the expected From address and self-addressed recipient. |
| Archive destination | Thunderbird's native configuration used All Mail. Send & Archive removed the intended Inbox labels, retained the messages and Sent labels, and added no Trash label. |
| Conversation scope | Reply to message 2 previewed 2 messages. After one confirmed send, only messages 1 and 2 lost Inbox membership. Newer message 3 and unrelated same-subject message 4 retained Inbox membership. New reply message 5 arrived in Inbox. |
| Gmail label preservation | A custom test label added to message 1 remained after archiving. |
| Reply identity / ancestry | Message 5 replied to message 2 with References containing messages 1 and 2. Exactly five synthetic messages existed after the send; no duplicate test reply was observed. |
| Thunderbird tags | Applying Work to message 4 displayed Work in Thunderbird. Gmail's label set was unchanged. This verifies the local tag path, not a Gmail label picker. |
| Trash | Palette Move to Trash moved only message 4 to Gmail Trash. The connector confirmed Trash membership, then restored it to Inbox. No test message remained in Trash at the final check. |
| N18 console noise | No popup-unload error or extension-source error was observed after the Gmail identity, send and tag paths. The console also contained native account-discovery, developer-tooling and synchronization diagnostics, so it was not globally error-free. |
| Final configuration | Send & Archive was disabled again after testing. The test subject filter remained active across folder changes. |

Final server checks asserted five known synthetic message IDs, Sent membership for all five, Inbox absence for messages 1/2, Inbox presence for messages 3/4/5, preservation of the test label on message 1, and no Trash membership. Raw account details and snapshots were not committed.

## Scope and remaining limits

The Gmail smoke-test gate passed for this account, configuration and installed build. This was a synthetic test in an owner-approved account, not a broad production-mail trial. A limited core-workflow trial is now supported by the evidence; keep Send & Archive off unless deliberately enabling it for a chosen workflow.

Thunderstream still offers Thunderbird tags rather than a Gmail label UI. Other Gmail identity heuristics, multi-account/window targeting, VoiceOver, dark theme and ambiguous send scenarios remained unverified in this initial Gmail run. A [continuation](2026-10-04-reliability-0.1.3.md) subsequently verified Gmail restart and disable/re-enable, and exercised additional local send failures. The broader MVP remains incomplete. PR #3 remains open; no new release or add-on marketplace submission was made.
